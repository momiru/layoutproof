# A02 implementation

The verifier distinguishes four observations of a rewrite. A result must preserve the output domain, the mapping from output coordinates to original logical coordinates, exact binary32 payloads, and the physical address map and write permission. Logical coordinates and value bits are checked separately, even when repeated values conceal a changed index. IEEE signed zero, infinities, subnormals and NaN payloads are carried as bits. No numerical tolerance or floating-point arithmetic is involved.

## Semantics

- Shape is a vector of unsigned extents. A scalar has one coordinate, the empty tuple. Any zero extent yields an empty domain. Cardinality is checked before coordinate evaluation. Empty layouts require an input origin between zero and capacity inclusive. Lowering canonicalizes empty strides and origin because there is no reachable element.
- A physical address is an abstract storage ID and an element offset. For index `i`, the offset is `origin + sum(i[k] * stride[k])`. The affine lowerer checks signed bounds through the extreme reachable corners and uses wide intermediates for 32- and 64-bit hosts. Singleton strides have no observable effect. There is no unsafe Rust or pointer reinterpretation.
- An exclusive input represents an injective lease over a reachable address region. `check_with_peers` validates the selected view and the caller-declared live peers as one context. Views with the same storage ID must agree on capacity, and every pair with an exclusive lease must have disjoint address sets. Bounds precede overlap rejection. Each supplied exclusive peer must itself be injective, even when it is disjoint from the selected view. Empty peers have no reachable addresses. Materialization may only use a fresh ID outside the declared live allocation set. Full equivalence also compares all IDs and capacities introduced by either program because a continuation can observe reservations. The lowerer uses interval exclusion and bounded exact intersection. The independent interpreter enumerates coordinates and checks per-allocation unions of reader and writer offsets. The caller supplies a complete peer set for the scope being checked. The single-layout entry point supplies an empty peer set. Broadcast yields read-only access and `RequireWritable` asserts a writable lease.
- Slice specifies an explicit start, count and nonzero signed step. Empty slices allow a start from zero through the axis extent. Coordinates of nonempty slices must all exist. Broadcast aligns trailing axes and can extend a singleton to any extent, including zero.
- Reshape preserves row-major logical order. The lowerer derives candidate strides from the origin and the target basis coordinates. It represents the address minus the origin as a sum of mixed-radix carry terms, each of the form `floor(flat / suffix) * coefficient`. Distinct suffixes below the domain size are independent, since the first differing term can be observed at its suffix. The independent interpreter evaluates the candidate basis at every coordinate. A non-affine reshape returns `RequiresCopy`. Explicit materialization into a fresh ID provides dense, exclusively writable storage. Repeated IDs in a program are rejected. Across the two alternative programs, equal IDs identify corresponding allocations by construction.

## Validation and proof scope

`lower` computes addresses and walks backward through program indexing to recover the input ordinal. `oracle` moves independently enumerated cells forward through each stage and checks actual bit payloads from the provided backing slice. In full mode both paths must agree before comparing programs. For materialized outputs the oracle simulates copied cells with new offsets, while the lowerer derives value provenance from the input. The procedures share the typed IR and its stated semantics.

`proof::affine_addresses` compares concrete affine maps through normalized origins and active-axis stride coefficients. The minimal witness is the zero index if origins differ, or the unit coordinate of the last differing active axis. `replay_fixed` checks the encoding and witness with the bounded interpreter. Z3 separately checks satisfiability and, for a witness, the absence of an earlier index. This is an address-only check. A shape or storage mismatch refutes equivalence before a solver query. `replay_fixed_with_peers` checks declared live peers in both implementations before comparing addresses.

`proof::certify` recognizes flip and transpose involutions, expand followed by squeeze, and checked nonempty slice fusion. The SMT obligation asserts that reference definedness implies candidate definedness and coordinate preservation. Flip and transpose require valid axes for the input rank. Discovery and replay use the rank ceiling imposed by the signed byte limit for the shape and stride vectors. This ceiling describes representable metadata and available memory can impose a smaller limit. Slice fusion requires valid start and last coordinates for both reference slices, while independent coefficient equalities bind the fused operation. The consequent only applies where the reference is defined. For instance, an invalid reference can still have a valid simplified candidate. `replay_on_layout` checks both programs on the supplied layout and declared peers before running the solver. Untouched axes are unchanged by construction. The replay trusts Z3 for the arithmetic result and the Rust translation for correspondence with the model. These are local conditional checks, with no machine-checked correspondence to the engines.

Replay the SMT-LIB obligation in a separate process:

```sh
set -o pipefail
cargo run --quiet --offline --locked --bin a02-layoutproof -- \
  --mode query --case C09-slice-fusion | z3 -in -smt2
```

`--timeout-ms 0` exercises `UNKNOWN` without starting a solver. Solver absence is `NOT_RUN`. Unsupported symbolic programs remain `UNSUPPORTED` unless a separate applicable check runs. `REJECTED` indicates an invalid input or certificate. `FAIL` indicates a failing candidate or a satisfiable negated obligation. `ERROR` covers infrastructure or conflicting checks.

## Live Momiru development checks

`adapters/a02_momiru.rs` invokes independently exported General and Light borrowed-view APIs at the revision in `Cargo.lock`. Light dispatches by actual rank, translates checked slices into its half-open endpoint convention and calls its native view operations. General calls checked count-based slicing; singleton-axis changes go through General's native reshape. Each engine exposes its checked offsets and returned references. The adapter checks that each reference points into the original backing buffer at the returned offset, then independently compares shape, offsets and FP32 payloads against the interpreter. No engine check grants write access to a read-only view. Mutable-view tests exercise real exclusive constructors and compare actual backing post-state with the interpreter's selected coordinate.

`--mode engine-check --engine both` reports per-variant observations and a separate rewrite verdict for each engine. Admission requires the full model check, including logical lineage and permissions, and equality of the two native observations. Rows marked `origin=oracle-preflight` report interpreter decisions before the native engine was called. The Light adapter uses end-relative coordinates when absolute indices exceed the signed endpoint range. Engine-check covers the supported borrowed-view subset, including ranks zero through eight for Light. Native noncontiguous reshapes and materialization or write assertions in the borrowed CLI path are `UNSUPPORTED`. The separate `check_materialization` API uses the native read view to gather the logical values and invokes the selected engine's owned constructor. It checks dense destination offsets, exact values, actual backing extent, and disjoint source and destination byte ranges for nonempty storage. Empty outputs have no address to compare. Model storage IDs are checked independently of physical pointers. The paper's `aot` Cargo feature forwards Momiru's feature for compilation and test coverage. It does not run device kernels or classify timing evidence.

## Experiments and provenance

Modes `finite`, `symbolic`, and `manual` select the bounded interpreter, supported symbolic laws, and the manual allowlist (literal identity, double flip, and expand/squeeze cancellation). `no-address` disables physical identity comparison. `no-alias` removes candidate write preconditions. The model API also exposes `NoLivePeerCheck`, which disables overlap checks between views and retains capacity, bounds, self-injectivity and write assertions. Benchmark admission excludes all ablations.

The CPU development runner can time model lowering or a native candidate view plus its observation. Native sampling starts after model and per-engine admission and each sample is compared against the validated observation after stopping the clock. Native timings include allocations for the observation and exclude backing initialization, the interpreter, sample comparison, and output drop. Warmups and samples are reported in order per engine. The process starts before any timed interval. Canonical evidence, hardware comparisons and aggregation remain gated. In default check mode a registered negative control returns exit 0 when its expected failure is observed. The printed decision is still `FAIL`.
